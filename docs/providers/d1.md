# D1 — integración en progreso

El diagnóstico cerrado del 2026-10-05 documenta una API de catálogo VTEX pública pero no contratada: `GET /api/catalog_system/pub/products/search`, `items[]`, `sellers[]` y el campo de origen `commertialOffer`. El contexto Medellín Sur corresponde a región de fulfillment, no a precio físico de sucursal. El seller comercial `1` no es el almacén logístico `12109`.

El cliente/mapper y la ruta de refresh manual online genérica existen. La búsqueda UI consulta SQLite sin tráfico remoto automático; solo el botón de actualización llama a D1 con límites de páginas, tamaño y cooldown. Se guardan producto/SKU/EAN, seller, oferta, precio de lista, cantidad raw y RAW gzip, con histórico de cambios relevantes. El adaptador `D1Provider` no está registrado en producción; su lectura regional exige sesión anónima aislada y revalidación antes y después de recuperar catálogo. La captura regional `D1RegionalCapture` permanece interna pese al smoke opt-in con SQLite efímera que pasó 1/1; ese resultado no habilita recomendaciones regionales de producción. Solo se atribuye `FulfillmentRegion`, nunca precio físico. Un contexto arbitrario no basta y no se guardan cookies ni OrderForm.

Siguen pendientes atributos adicionales y promociones estructuradas sustentadas por evidencia, health regional por capability y un lifecycle RAW/backup portable. La metadata opcional de URL/categoría y las métricas locales de sync ya se conservan; el smoke regional opt-in pasó con SQLite efímera, sin probar precio físico de sucursal ni todas las variantes de detalle. No evadir 403/429.

El contraste con `source_archives/diagnostics-cierre.rar` (`diagnostics/results/d1-location-context-http-v2.json`) muestra `facets` serializado como pares `key=value;`, incluyendo `coordinates=-75.5932585,6.232177;`, y 400 en inicialización seguido por segmentos exitosos en tres sesiones. La comparación literal del código coincide con esa captura, pero su estabilidad futura no está garantizada; un formato diferente invalida la región en vez de etiquetar una cotización sin prueba. La revalidación HTTP fallida invalida la sesión en memoria. El payload de navegador archivado tiene otros campos/diferente `isDisposable`; el smoke live opt-in de una sesión pasó, pero no basta para registrar la ruta regional en producción.

La búsqueda textual ahora consulta como máximo tres páginas de 20 (`_from`/`_to`) y deduplica IDs; esto **no** equivale a enumeración completa. El diagnóstico halló que `ft` por nombre largo puede devolver 400 y que `ft` por EAN/ID no es confiable; no se ha demostrado fallback de búsquedas; el smoke regional opt-in ejercitó `fq=productId` para un único producto en una sesión. Los tests offline de paginación no prueban compatibilidad del servidor actual.

Persistencia offline parcial: `D1CatalogIngest` acepta capturas `online-generic` y la ruta interna regional verificada, usa transacciones SQLite para producto/SKU/seller/oferta y vincula RAW gzip/SHA-256 con observaciones de cambios. JSON/schema drift se rechaza antes de escribir y conserva el último precio válido. `D1SearchSync` conecta HTTP a ingest genérico con `SyncRun`; la ruta regional permanece interna. El RAW escrito antes de rollback puede quedar huérfano y requiere lifecycle/retención. `ListPrice` y cantidad raw ya se guardan en `Offer`; faltan promociones estructuradas y atributos adicionales sustentados por evidencia.

Existe una ruta **manual y acotada** para refrescar búsqueda online genérica (`POST /api/v1/providers/d1/refresh?q=...`), con límite de tres páginas de 20, un único refresh simultáneo, cooldown local de 30 s, timeout 15 s, `SyncRun` y respuesta explícita ante 403/429, HTTP/schema drift. La consulta local `GET /api/v1/providers/d1/offers?q=...` expone solo ofertas guardadas con contexto y fecha; la UI no las rotula como precio físico. Un fallo de refresh conserva ofertas de páginas ya confirmadas y las anteriores, pero la operación global queda `FAILED`; la política de lotes/consistencia regional, datos incompletos y validación live siguen pendientes. La UI solo refresca tras acción explícita. No está demostrado un smoke live de esta ruta y las capacidades se anuncian como `PARTIAL_GENERIC_ONLINE_MANUAL_REFRESH`, no como integración D1 completa.

Pruebas adicionales del refresh con HTTP simulado y SQLite migrada: una segunda página con 429 o cancelación marca `SyncRun.FAILED` sin borrar las 20 ofertas confirmadas en la primera página; HTTP 403/500, página vacía y respuesta mayor a 2 MiB mantienen el estado consistente. Una página vacía no significa que se haya probado que un producto desapareció del catálogo. La UI calcula frescura de precio usando el TTL de ajustes (6 h por defecto) y etiqueta un dato vencido/antiguo como último dato conocido, sin convertir `UNKNOWN` de disponibilidad en stock. Son verificaciones offline y no validan compatibilidad live.

La ruta de lectura online genérica filtra explícitamente `PriceScope.OnlineGeneric` y `Context=online-generic`; no expone por accidente otra oferta regional/física futura como genérica. Un test API con base temporal comprueba la separación de ámbito y retailer. El timeout HTTP se registra `TIMEOUT` frente a `CANCELLED` del cliente, sin revelar detalles al frontend.

La migración `D1OfferQuantity` agrega `Offer.AvailableQuantityRaw` (nullable, decimal) y el mapper preserva `ListPrice` positivo y la cantidad ecommerce bruta cuando están presentes. El sentinela `99999` permanece solo como dato bruto: la UI muestra disponibilidad lógica online y jamás unidades exactas de góndola. `PromotionConditions` se propaga si el contrato aporta condiciones, pero el parsing estructurado de promociones D1 aún no está implementado; no inferir condiciones del descuento simple. Tests SQLite/migraciones antiguos y actuales cubren la adición.

Ruta regional **interna, no registrada como endpoint de usuario**: `D1RegionalCapture` establece sesión anónima, revalida `regionId`/canal/coordenadas antes y después de consultar detalle por `fq=productId`, exige coincidencia exacta del ID solicitado y llama al ingest interno con `PriceScope.FulfillmentRegion`. `D1CatalogIngest.SaveAsync` público sigue rechazando contexto regional arbitrario. Pruebas offline con HTTP sintético y SQLite verifican rechazo de región cambiada, producto distinto y schema drift antes de escribir; el smoke opt-in integrado pasó 1/1 con SQLite efímera; no certifica otras identidades, regiones o disponibilidad futura del filtro. No afirma precio físico.

El refresh manual reintenta una sola vez errores transitorios 500/502/503/504 o de transporte, con pausa cancelable de 150 ms; jamás reintenta 403/429. `RawStore.CleanupOrphansAsync` puede ejecutarse explícitamente para limpiar archivos hash antiguos sin registro SQLite; aún no existe política automática de retención de RAW indexado. No se borran observaciones ni capturas referenciadas por precio vigente.

La métrica local `SyncRun.ItemsReceived` representa filas de catálogo de páginas validadas y confirmadas en SQLite por el refresh manual, incluso si una página posterior falla. No es número de productos únicos ni inventario, y `OffersSeen` indica ofertas procesadas; otros contadores solicitados siguen pendientes. Las corridas anteriores a la migración tienen cero por defecto sin afirmar que se midieron.

La ruta local `GET /api/v1/providers/d1/health` muestra capabilities declaradas como parciales o no soportadas y la última corrida con resultado y filas recibidas. No comprueba conectividad actual ni habilita el adaptador regional: un estado de corrida anterior tampoco acredita disponibilidad presente del proveedor.

Cuando la respuesta contiene el mismo `productId` en filas distintas, el mapper reúne los SKUs por ID y conserva la primera identidad de producto; evita perder presentaciones de filas duplicadas. Esta es cobertura de fixture offline, no prueba de categorías live.

La búsqueda de lectura acotada también fusiona SKUs del mismo producto entre páginas; conserva la primera identidad textual, deduplica por ID de SKU y nunca convierte esa fusión en evidencia de precio físico.

`SyncRun.OffersProcessed` registra el total de ofertas procesadas de páginas confirmadas, distinto de `ItemsReceived` y de ofertas únicas. Los valores cero previos a la migración son defaults sin medición histórica; ambos contadores se muestran solo como evidencia local.

`RawStore.CleanupExpiredUnreferencedAsync` permite poda **manual** de capturas antiguas sin referencias de ofertas/histórico, tras validar hash y ruta esperados; no elimina evidencia referenciada. No existe todavía una programación ni política configurable de 60 días y los backups SQLite no incluyen ficheros RAW. No ejecutarla sobre datos de usuario sin evaluar backup y política de retención.

Si dos apariciones del mismo SKU discrepan en nombre, EAN o cantidad/dimensión normalizada, el mapper rechaza el payload; no elige una equivalencia arbitraria. Filas idénticas por SKU se deduplican.

Cotizaciones repetidas del mismo SKU+seller dentro de un mismo payload deben ser idénticas; discrepancias de precio/estado se tratan como schema drift y no se elige un precio sin evidencia adicional.
